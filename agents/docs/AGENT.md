# Documentation Agent Guide

Use this guide for README, docs, ADR, and project guidance updates.

## Principles

- Preserve project facts from existing files; do not invent commands, services, or deployment details.
- Keep docs close to the reader's task: setup, architecture, operations, or decision history.
- Prefer short examples, exact commands, and links to source files over broad advice.
- Update `CLAUDE.md`, `AGENTS.md`, or `agents/**/AGENT.md` only when the instruction will help future agents.

## ADRs

Store architecture decisions under `docs/adr/`. Include context, decision, consequences, and date. Keep decisions stable and avoid issue-specific chatter.
